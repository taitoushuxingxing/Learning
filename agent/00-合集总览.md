## 二、四篇共用的那张图：Agent 8 层

EP01 立起来的骨架，后面三篇各自嵌进去：

```
L0  模型底座        LLM —— 唯一不属于 Harness 的一层
L1  内核层          Prompt / Workflow / ReAct / Plan（混合，不是四选一）
L2  行动层          Function Calling → MCP → CLI
L3  记忆层      ◀── EP03 展开（Session / Task State / Long-term / Data-derived）
L4  上下文层    ◀── EP02 展开（分层 / 按需加载 / 压缩 / 保护区 / 隔离）
L5  边界层          稳定性 + 四道安全墙（租户 → 工作空间 → 沙箱 → 网络）
L6  协作层          Multi-Agent：分层 / All-in-One / 辩论 / 通信
L7  工程层      ◀── EP04 展开（Trace → Eval → 灰度）
L8  进化层          Bad case 闭环、对抗熵增、人机协作
```

**读的时候拿这张图当索引**：任何一篇讲到一个具体做法，先问它是哪一层的问题、归哪个模块管。

## 三、建议阅读顺序

**01 → 02 → 03 → 04**，别跳。

理由：01 给的是坐标系，02 和 03 大量使用「这是 L4」「这属于 L3」的说法；先读 02/03 会觉得在背零散技巧，读完 01 再看才发现它们是同一个系统里的两个抽屉。04 放最后，因为它默认你已经有一个跑起来的 Agent 才谈得上评测。

时间紧的话：

- **只想知道 Agent 怎么设计**：01 必读，02 的「六条策略」速览
- **Agent 记不住事、越聊越蠢**：直接 02 + 03，这两篇讲的正是这个病
- **要向老板证明 AI 有用**：04，尤其第 12 章「把感觉换成数字」

## 四、三篇之间的关键分界线（最容易混的地方）

| 问题 | 归谁管 | 一句话判据 |
|---|---|---|
| 这轮对话里能看到什么 | 上下文（L4 / EP02） | 一次会话内的事，会话结束就没了 |
| 上次那个项目定过什么规范 | 记忆（L3 / EP03） | 跨会话还在的事，要能主动写回与取回 |
| 这个改动到底变好没变好 | 评测（L7 / EP04） | 需要版本号、基线、可比较的数字 |

三篇里反复出现同一个警告：**不要把 Memory 当 Context 用，也不要把 Context 当 Memory 用**。前者会让你把整个知识库塞进窗口，后者会让 Agent 每次开工都从零开始。

## 六、一个需要留意的来源差异

第 4 篇（Langfuse）来自《Agent 系统设计》系列，那套共 6 集，本目录只收了第 5 集：

```
Agent系统设计 01：意图识别
Agent系统设计 02：如何评测（单意图评测）
Agent系统设计 03：如何评测（多意图）
Agent系统设计 04：Agent架构选型
Agent系统设计 05：用 Langfuse 搭建 AI Coding 评测与改进闭环   ← 本目录收录
Agent系统设计 06：LLM Context Engineering
```

也就是说，第 4 篇里提到的「评测分工」「意图」等前置概念，在原系列里是有铺垫的，这里直接从第 5 集切入。读的时候如果觉得某些前提没交代，那不是笔记漏了，是**上游那 5 集没看**。
