## 1. 第一章 开局：脚手架与项目结构

### 1.1 两种建项目方式

| 方式 | 做法 | 场景 | 作者判断 |
|---|---|---|---|
| 引入文件 | 像早期 Vue 一样在 HTML 里引 `react.js` | 单页 demo、给老页面加交互 | 可行，不推荐 |
| **脚手架** | `npx create-react-app` | 真实项目 | **「项目中更加常用」**，直接演示这个 |

```bash
npx create-react-app my-react-app   # 建项目 + 自动装依赖
cd my-react-app && npm start        # 起服务，浏览器开 :3000
```

`npx` 是 npm 自带的临时执行命令，跑完即弃，所以作者说**「不需要全局做安装」**；`create-react-app` 是 React 官方脚手架，社区简称 **CRA**；`my-react-app` 是项目名兼目录名。

📌 补充（拍视频时还不成立）：**CRA 已于 2025 年 2 月被官方停止维护**，现在推荐 Vite：`npm create vite@latest my-react-app -- --template react`。对本集语法**零影响**，只是入口从 `src/index.js` 变成 `src/main.jsx`。**跟着视频学语法、用 Vite 建项目**最省事。

### 1.2 目录：只需盯住两个文件

```
my-react-app/
├── public/index.html      # 唯一 HTML，里面必有 <div id="root"></div>
├── src/
│   ├── index.js           # ★ 入口
│   ├── App.js             # ★ 根组件
│   └── reportWebVitals.js # 可删
└── package.json
```

### 1.3 `index.js`：入口只做三件事

```jsx
// src/index.js（按口述还原）
import React from 'react';
import ReactDOM from 'react-dom/client';     // ① 引入两个库
import App from './App';                     // .js 后缀可省

const root = ReactDOM.createRoot(document.getElementById('root'));  // ② 创建根

root.render(                                 // ③ 渲染根组件
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

| 步骤 | 作者原话 | 实际含义 |
|---|---|---|
| 引库 | 「引入两个关键的库，一个 react，一个 reactDOM」 | `react` 提供组件与 Hook，`react-dom` 负责写 DOM |
| `createRoot` | 「创建了一个 React 的实例」 | 指定渲染到哪个 div，React 18 新 API |
| `render` | 「进行了一个根组件的渲染」 | 把 `<App />` 这棵树挂上去 |

`public/index.html` 里必须有 `<div id="root"></div>`，否则 `getElementById` 拿到 `null`，直接报错。

**`StrictMode`** 被作者称为「严格模式，可以帮助组件内部做一些功能审查」。📌 补充：真实行为——开发环境下**组件函数故意调用两次、`useEffect` 故意执行两遍**（挂载 → 清理 → 再挂载），用来暴露「副作用没清理」「更新函数不纯」；生产构建不重复。所以看到 `console.log` 打两遍**不是 bug**。已有笔记的 Next.js 项目默认没开，从 CRA 迁过来的人常被吓到。

### 1.4 可以删掉什么

作者的建议很实用：「这两个文件是刚学 React 时最重要的文件，**其他文件你都可以删掉，并把相关的引入也删掉**」。`logo.svg`、`App.test.js`、`reportWebVitals.js` 先全删，`App.js` 清理成只剩一个返回：

```jsx
// src/App.js
function App() {
  return <div>Hello React</div>;
}
export default App;
```

## 2. 第二章 组件与 JSX 的四条硬规则

### 2.1 一个函数就是一个组件

```jsx
function App() {            // 普通函数
  return <div>内容</div>;   // 返回一段 JSX
}
export default App;         // 默认导出，供 index.js 使用
```

作者原话：**「React 里面的组件就是一个函数形式。」** 没有 `new`、没有继承、没有 `this`。根组件也不特殊——**「根组件跟其他组件在语法使用上没有区别，它只是一个层级上的关系」**。

React 有**两种**组件写法，作者当场对比并说明为什么只讲一种：

| 维度 | 函数组件 | 类组件 |
|---|---|---|
| 写法 | `function App() { return <div/> }` | `class App extends Component { render() {...} }` |
| 代码量 | 少 | **「十分复杂和冗余」** |
| 状态 / 生命周期 | Hook（`useState` / `useEffect`） | `this.state` + 一堆 `componentDidMount` |
| 官方态度 | **主推** | 维护，不再推荐新代码 |
| 存量 | 新项目主流 | 「以前的很多项目还是使用的类组件」 |

📌 补充：视频后面说「函数式组件默认是没有状态的」，准确理解是「**不加 Hook 就没有**」。Hook 之后函数组件完全有状态，这正是它取代类组件的原因之一；「函数组件 = 无状态组件（stateless component）」是旧称。

### 2.2 JSX 是什么

作者定义：**「它直接将 JavaScript 语法跟 HTML 语法书写在了一起，这种语法叫做 JSX」**，并定性——**「相比 Vue 的模板语法，JSX 将 HTML 和 JavaScript 结合得更加深入」**。展开就是：Vue 用 `v-for`/`v-if` 这类指令，JSX 直接用 `map` 和三元；Vue 模板是「加强版 HTML」，**JSX 本质就是一个 JS 表达式**，编译成函数调用。所以前提也不同——写 Vue 要记指令，写 JSX 要会 JS。

📌 补充：JSX 最终编译成 `React.createElement(type, props, ...children)`（React 17+ 用新 `jsx()` 运行时，可不再 `import React`）。这就是「大括号里只能放表达式」的由来——它对应一个函数参数。

### 2.3 规则一：`return` 换行必须加括号

```jsx
return (                // ✅ 换行就加括号
  <div>{divContent}</div>
);
```

作者现场把括号删掉、`return` 后直接换行写 `<div>`，结果——**「虽然现在没有报错，但 HTML 部分变成了一个浅灰的效果。」** JSX 变灰 = 不再被识别；保存后页面空白。原因是 **JS 的自动分号插入（ASI）**：

```javascript
return
  <div>内容</div>
// 引擎理解成：
return;                  // ← 自动补分号，函数直接返回 undefined
  <div>内容</div>        // ← 永远执行不到的表达式语句
```

作者的结论：**「无论单行还是多行，都建议书写上这个括号。」**

### 2.4 规则二：只能有一个根元素

同级再放一个 `<div>`，作者说「我还没有保存就发现已经有错误了，这块写了一个编译出错」，报错大意 `Adjacent JSX elements must be wrapped in an enclosing tag`。原因是 `return` 只能返回**一个**值；两个并排标签 = 两个值 = 语法错。三种解法：

| 解法 | 写法 | 优点 | 缺点 |
|---|---|---|---|
| ① 内层包裹 | 用已有 `<div>` 包 | 最简 | 多一层 DOM |
| ② 外层加容器 | 外面再套 `<div>` | 直观 | 多一层无意义 DOM，可能破坏 flex 布局 |
| ③ 空标签 | `<>` … `</>` | **不产生真实节点** | **不能加 key**（见第 6 章） |

作者的适用判断：**「如果你不想加额外容器」**就用空标签，并给了一个形象的描述——**「它并不是一个真实的标签，最终在渲染的时候，这个结构也不会产生任意的内容。」**

### 2.5 规则三：标签必须闭合

> **「无论你是单标签还是多标签，都需要正确地进行闭合。」**

HTML 里 `<img>`、`<br>` 可以不闭合，**JSX 不行**。作者在 `index.js` 找了现成例子：`<App />` 删掉斜线就报「没有匹配相应的结束标记」。

### 2.6 规则汇总

| # | 规则 | 错误 | 正确 | 现象 |
|---|---|---|---|---|
| 1 | `return` 换行要括号 | `return` 换行 `<div/>` | `return (` … `)` | **无报错**，页面空白 |
| 2 | 只能一个根元素 | `return (<a/><b/>)` | `return (<><a/><b/></>)` | 编译报错 |
| 3 | 标签必须闭合 | `<img>` | `<img />` | 编译报错 |
| 4 | `class` → `className` | `<div class="box">` | `<div className="box">` | 控制台警告 |
| 5 | 组件名首字母大写 | `function app()` | `function App()` | 当 HTML 标签，不渲染 |

> 第 4、5 条已有笔记 §2.3 讲过，此处只做归位。

## 3. 第三章 插值：大括号是 JSX 的取景框

### 3.1 内容插值

作者称它为**「JSX 中使用频率最高的插值功能」**，其实前面已见过——HTML 中间那个大括号。

```jsx
function App() {
  const divContent = '标签内容';
  return <div>{divContent}</div>;   // 页面显示：标签内容
}
```

他给了一条实用建议：**「这个数据如果是跟组件单独相关的话，我建议你直接书写在组件内部。」** 即作用域最小化：只在本组件用 → 写函数体内；多个组件用 → 提到父组件用 props 传（本集未讲，见已有笔记 §6）；全局共享 → Context（已有笔记 §10）。

### 3.2 属性插值：引号陷阱

```jsx
<div title={divTitle}>{divContent}</div>   // ✅ 浮层显示「标签标题」
<div title="divTitle">{divContent}</div>   // ❌ 浮层显示 divTitle
```

作者的判断一针见血：**「如果你加了一个双引号，那它就只能是一个普通属性了，而属性的值就是我们内部填充的一个文本。」**

| 写法 | 浏览器看到的 title | 含义 |
|---|---|---|
| `title={divTitle}` | `标签标题` | ✅ 表达式，取变量 |
| `title="divTitle"` | `divTitle` | ❌ 字符串字面量 |
| `title="标签标题"` | `标签标题` | ✅ 但**写死**，变量改了不变 |
| ``title={`${divTitle}！`}`` | `标签标题！` | ✅ 拼接仍在大括号内 |

**记忆法：引号 = 写死，大括号 = 求值。**

### 3.3 大括号里能放什么

| 放什么 | 例子 | 结果 |
|---|---|---|
| 变量 / 表达式 / 函数调用 | `{a + b}`、`{getName()}`、`{list.map(...)}` | ✅ |
| 对象属性 | `{user.name}` | ✅ |
| **对象本身** | `{user}` | ❌ `Objects are not valid as a React child`（第 9 章） |
| **`if` / `for` 语句** | `{if (x) {}}` | ❌ 只能放表达式；条件用三元或提前算好变量 |
| 注释 | `{/* 注释 */}` | ✅ JSX 里唯一的注释写法 |

> 「不能放语句」正好解释了下一章为什么要「先算好变量再插值」——他没法把 `if` 塞进大括号。

## 4. 第四章 条件渲染：一个 flag 两种标签

### 4.1 视频的写法：变量 + if + 插值

```jsx
function App() {
  const flag = true;
  let divContent = '';                        // 先声明空壳

  if (flag) {
    divContent = <span>我是 span 内容</span>;   // 赋的是 JSX，不是字符串
  } else {
    divContent = <p>我是 p 内容</p>;
  }

  return <div>{divContent}</div>;
}
```

作者特意点出：**「这块我们直接结合的是 JSX 语法的内容，所以书写起来非常简单。」** 赋给 `divContent` 的是**一段 JSX**，这跟传统 DOM 编程的直觉完全不同。

### 4.2 为什么不用字符串拼接

> **「JSX 是 JavaScript 跟 HTML 结合的模板语法，所以我可以直接将 HTML 跟 JavaScript 混写，不再需要像以前一样写一个字符串的结构、不再需要做拼接。可能刚开始接触 JSX 会觉得非常疑惑，但这其实就是 JSX 的简便之处。」**

```javascript
// ❌ 传统 DOM 思维：拼字符串 + innerHTML
let html = '';
if (flag) html = '<span>我是 span 内容</span>';
container.innerHTML = html;   // 没类型检查、没法绑事件、有 XSS 风险
```

两者差在本质：拼字符串产出的是**文本**，JSX 赋值产出的是**对象**（虚拟 DOM 节点）。所以 JSX 里能绑事件（`<span onClick={fn}>`）、能嵌组件（`<MyComp />`）、拼接错误在编译期就红，且 React 默认转义不用担心 XSS。

### 4.3 现场验证：F12 看真实 DOM

> **「点击 F12 选中这个标签，看到现在是一个 span。我尝试将 flag 改为 false 保存，这里就变成了一个 p 标签。」**

**元素是真的被替换，不是隐藏**——条件渲染时 DOM 里没有节点；CSS 隐藏时节点还在。📌 补充：所以条件渲染每次「销毁 → 重建」，**子树里的 state 会丢**（表单切走再切回，输入框就空了）。要保留状态：用 CSS 隐藏，或把状态提到父组件。

### 4.4 三种条件写法各用在哪

视频只演示「变量 + if」，因为它最贴近传统思维。工程里三种都用，已有笔记（§7.3、§7.4）讲的是后两种：

| 写法 | 代码 | 适合 | 坑 |
|---|---|---|---|
| **变量 + if**（本集） | `let c=''; if(f) c=<A/>; else c=<B/>` | 分支多、逻辑长 | 行数多，但可读性最好 |
| **三元** | `{f ? <A/> : <B/>}` | 两分支、行内 | 嵌套三元变括号地狱 |
| **`&&`** | `{f && <A/>}` | 有就显示 | **左边是 `0` 会渲染出 0**（已有笔记 §7.4） |
| **提前 return** | `if (loading) return <Spin/>;` | 整页互斥状态 | 只能用于组件顶层 |

选型一句话：**局部片段切换用三元或变量 + if；整页互斥用提前 return。**

## 5. 第五章 列表渲染与 key

### 5.1 为什么用 `map` 而不是 `for`

> 「可以通过 for 循环或者通过 map 的方式来处理。为什么用 map 呢？因为 map 是**具有返回值**的，我们就可以将每个数组元素拼接成 JSX，然后再放入模板中。」

`for` 是语句、`forEach` 永远返回 `undefined`，都不能直接插值；**只有 `map` 返回新数组**，所以 `{list.map(...)}` 能直接用。

```jsx
const list = ['小吴', '小李', '小花'];
const listContent = list.map((item) => <li>{item}</li>);
return <ul>{listContent}</ul>;
```

作者还提醒：`<li>{item}</li>` 里的 `{}` 是**又一次插值**，因为那已经在 JSX 内部了。

### 5.2 报错现场

一保存页面正常，但他立刻去看控制台：**「`Each child in a list should have a unique key prop`，它需要一个唯一的 key 属性。」**

```
Warning: Each child in a list should have a unique "key" prop.
```

这是 **Warning 不是 Error**，页面照常显示，所以很多人忽略。作者坚持修，因为 **「key 用来在虚拟 DOM 中保证当前元素的唯一性」**。

📌 补充——key 决定「正确性」而不只是「消警告」：React 更新列表时对新旧虚拟 DOM 做 Diff，**key 是它认人的身份证**。key 相同 → 认为同一个元素，复用 DOM 和 state；key 不同 → 销毁重建。没 key，React 退化到按下标对比，一旦插入/删除/排序就「张冠李戴」。

### 5.3 唯一性是「同级唯一」

作者给了一个很少人说的精确定义：**「这个唯一，指的是在同级中是唯一的就可以了。」**

```jsx
// ✅ 合法：两个列表各有一组 1、2、3，互不干扰
<ul>{listA.map(i => <li key={i.id}>{i.name}</li>)}</ul>
<ul>{listB.map(i => <li key={i.id}>{i.name}</li>)}</ul>
```

### 5.4 为什么不能用下标

作者很干脆：**「如果用下标来写的话是不 OK 的，因为下标随着元素变化，它并不是针对每一个元素唯一。」** 这和已有笔记 §8.3「index 勉强能用」有程度上的冲突（详见第 15 章）。先看翻车现场（📌 补充）：

```jsx
{list.map((item, index) => (
  <li key={index}><input placeholder={item} /></li>
))}
```

在**头部插入**一项 `'X'`：

```
插入前            插入后
index 0 → A       index 0 → X   ← key 0 被复用但数据变了，输入内容留在原地
index 1 → B       index 1 → A   ← key 1 被复用，内容错位
index 2 → C       index 2 → B
                  index 3 → C
```

结果：**你在 A 的输入框里打的字，跑到 X 那一行了。** 下标代表「位置」，不代表「身份」。

### 5.5 修法：把数据结构升级

作者的修法不是「加个 index」，而是**改数据形态**：**「更加建议的是将你的数据更改为另外一种形态，比如说将每个数据都加上一个 ID」**，并强调 id 不该前端造——**「应该是后端给我们返回的数据中就会具有相应的 ID」**。

```jsx
const list = [
  { id: 1, name: '小吴' },
  { id: 2, name: '小李' },
  { id: 3, name: '小花' },
];
return (
  <ul>{list.map((item) => <li key={item.id}>{item.name}</li>)}</ul>
);
```

改完刷新，**报错消失、内容正常**。作者总结：**「这个 key 属性就可以帮助我们在任意情况下确保渲染的正确性。」**

## 6. 第六章 循环里的多根元素：Fragment 的用武之地

这一章是本集**最有辨识度**的部分，已有笔记完全没有涉及。

### 6.1 事故：每个 li 下面加一条分割线

需求：「每次不光要渲染一个 li，我还希望在你每一个 li 底下添加一个分割线」（他说实际项目用 CSS 就行，这里为演示语法）：

```jsx
const listContent = list.map((item) => (
  <li key={item.id}>{item.name}</li>
  <hr />                        {/* ← 第二个根元素 */}
));
```

立刻踩回第 2 章那条规则：**「你的 JSX 必须只能有一个根元素，它在我们这个区域是同样有效的，因为它也是 JSX。」** 注意 `map` 的回调返回的**也是一个 JSX 表达式**，所以单根约束在每一轮循环里独立生效。

### 6.2 空标签为什么不能加 key

第一反应是用空标签包（单根解决了，key 报错又回来了——key 必须加在最外层，而最外层是 `<>`）：

```jsx
< key={item.id}> ... </>   // ❌ 语法错误：<> 是简写，不接受任何属性
```

作者原话：「这种结构是一个类似于 `documentFragment` 的结构，但它并不能真正地生成，**这个地方如果你给一个 key 的话是不可以的**。」📌 补充：原因——`<>...</>` 只是 `<React.Fragment>` 的**语法糖**，编译时直接替换，**没有位置写属性**。

### 6.3 正确解：`<Fragment key={...}>`

> 「我们就可以使用 React 提供的一个 Fragment 标签，就跟 document fragment 是一样的。你直接书写，它就会在顶部帮你做一个引入。它是在 react 中包含的一个功能，你可以把它的名称当作标签来用，**它其实是一个组件的结构**。」

```jsx
import { Fragment } from 'react';

return (
  <ul>
    {list.map((item) => (
      <Fragment key={item.id}>
        <li>{item.name}</li>
        <hr />
      </Fragment>
    ))}
  </ul>
);
```

验收：**「这个设置是没有问题的，我们呈现还是没有问题的，我们底部的一个报错也是不存在的。」**

| 方式 | 产生 DOM | 能加 key | 用在哪 |
|---|---|---|---|
| `<div>` | **会** | ✅ | 需要这层做样式/布局 |
| `<>...</>` | 不会 | **❌** | 静态结构里合并多根 |
| `<Fragment key>` | 不会 | **✅** | **循环里每项多根元素** |

### 6.4 为什么 Fragment 存在（📌 补充）

它解决「**既要多个兄弟节点，又不想污染 DOM**」这个矛盾，典型场景是**HTML 语义不允许中间夹 `div`**：表格一行要返回多个 `<td>`（`<tr>` 由父组件写），若包一层 `<div>` 就变成 `<tr><div><td/>…` ——非法，浏览器会乱修。同理还有 `<dl>` 里的 `<dt>/<dd>`、`<select>` 里的 `<option>`。这时只能用 `<>` 或 `<Fragment>`。

## 7. 第七章 事件：onClick 与驼峰命名

> 「可以在标签内部采用 `onClick` 的方式写在 JSX 里，我们的属性通常都是以**驼峰**的形式书写的。后面需要给的是一个事件处理程序，函数需要给一个大括号。」

```jsx
function App() {
  function handleClick() {          // 函数就定义在组件里
    console.log('点击了按钮');
  }
  return <button onClick={handleClick}>按钮名称</button>;
}
```

要点只有两条：事件名用**驼峰**（`onClick` 不是 `onclick`）；值是**大括号包函数引用**（`onClick={handleClick}`，**不带括号**）。

**事件对象 `e`**：**「可以接收一个参数 `e`，这跟我们之前做 DOM 操作比较类似，里面包含了一些鼠标相关的坐标之类的内容。」** 常用 `e.target.value`（输入框值，受控组件核心，已有笔记 §9.2）、`e.preventDefault()`（阻止表单刷新）、`e.stopPropagation()`、`e.clientX/Y`。

📌 补充：React 给你的是 **SyntheticEvent（合成事件）**，跨浏览器包装，API 基本一致，但**处理函数执行完后对象会被回收**（React 17 之前）。要在异步回调里用，先取值存变量：`const v = e.target.value;`。

**加不加括号**（最高频错误，已有笔记 §9.1 提过）：

```jsx
<button onClick={handleClick}>点我</button>                   // ✅ 点击时才执行
<button onClick={handleClick()}>点我</button>                 // ❌ 渲染时立刻执行，把 undefined 给了 onClick
<button onClick={() => handleDelete(item.id)}>删除</button>   // ✅ 传参标准写法
```

## 8. 第八章 状态：为什么普通变量改了界面不动

### 8.1 事故复现

```jsx
function App() {
  let divContent = '默认内容';

  function handleClick() {
    divContent = '新内容';
    console.log(divContent);      // 控制台确实打印「新内容」
  }

  return (
    <div>
      <div>{divContent}</div>
      <button onClick={handleClick}>点击</button>
    </div>
  );
}
```

> **「点击 F12，控制台里是没有任何报错的，输出都是正常的。但是我们的内容就是没有做更改。」**

### 8.2 为什么

作者用 Vue 做对照：

> **「在 Vue 中可以声明一种响应式数据，它会直接驱动页面更新，这是前端框架减少 DOM 操作的手段。而在 React 中，函数式组件默认没有这种状态机制，意味着你这个数据只是一个普通变量，你把它改了也没有任何意义。」**

原因就两句：普通变量只是函数里的局部变量，**函数执行完就没了，React 根本不知道它变了**；只有**调用 `setXxx`** 时，React 才收到「需要重新执行这个组件」的信号。

```javascript
function App() {
  let divContent = '默认内容';   // ← 每次渲染都重新创建、重新赋值
  // 你在 click 里改的，是「上一次渲染时那个作用域里的变量」
}
```

📌 补充：「console 里有值」是因为你改的确实是内存里那个变量，只是**没人拿它重新生成界面**。React 的渲染就是「执行函数 → 返回 JSX」，不执行函数，JSX 不会重算。

### 8.3 `useState` 拆解

引入方式：**「我们需要使用一个新的功能叫做 `useState`，它是 React 提供的一个函数，直接一回车它就可以帮你引入。」**

```jsx
import { useState } from 'react';

function App() {
  const [content, setContent] = useState('默认内容');

  function handleClick() {
    setContent('新内容');
  }

  return (
    <div>
      <div>{content}</div>
      <button onClick={handleClick}>点击</button>
    </div>
  );
}
```

| 部分 | 作者原话 | 说明 |
|---|---|---|
| `useState('默认内容')` | 「传入一个参数，就是你这个数据的初始值」 | **只在首次渲染生效**，后续忽略 |
| 返回值 | 「函数调用以后会返回给我们一个数组」 | 固定两个元素 |
| `[content, setContent]` | 「通过解构方式直接取出来」 | 名字随便起 |
| 第一个值 | 「代表的是**本次渲染的一个数据内容**」 | 只读 |
| 第二个值 | 「用来修改这个状态」 | **唯一的修改入口** |

作者一句话概括分工：**「一个用来读，一个用来改。」**

### 8.4 更新链路（📌 补充）

```
点击 → setContent('新内容') → React 存新值、标记组件待更新
   → 重新调用 App()（重渲染）→ 这次 useState 返回的 content 已是 '新内容'
   → 新 JSX → 新虚拟 DOM → Diff → 只把变化的文本写进真实 DOM
```

注意：**这一次初始值参数被忽略了**。这不是 bug——React 用「调用顺序」而不是变量名来记住每个 state 的位置。

### 8.5 为什么不是所有变量都做成状态

> **「如果每个变量默认都具备这种状态机制，那页面的负担是非常大的，也是不合理的。因为每个组件中通常只会存在一两个、两三个状态，而不会每个变量都是状态。」**

背后是 React 的取舍——**显式优于隐式**：代价是手动声明，收益是渲染时机完全可控。所以 React 的性能问题通常来自「状态放错层级」，而不是「框架追踪太慢」。

## 9. 第九章 对象状态：set 是整体替换，不是合并

本集**技术含量最高**的一章。已有笔记 §4.6 只说了「更新对象要用展开运算符」，没讲**为什么必须**。视频用一次翻车把这个「为什么」讲透了。

### 9.1 第一个坑：对象不能直接渲染

```jsx
const [data, setData] = useState({ title: '默认标题', content: '默认内容' });
return <div>{data}</div>;      // ❌
```

> **「我们这种对象结构是不能在视图中直接呈现的。这样写你会发现这块就会报一个错误，说的是 `Objects are not valid as a React child`，你不能把这个对象值直接作为 react 的子节点来进行渲染。」**

| 能不能插值 | 类型 |
|---|---|
| ✅ | 字符串、数字、JSX 元素、数组 |
| ❌ | **普通对象**；`undefined` / `null` / 布尔值（这三个是「什么都不渲染」） |

正确做法：`<div title={data.title}>{data.content}</div>`。作者验证：**「都是没有问题的，内容设置成功。」**

### 9.2 第二个坑：只写一个字段，另一个消失

```jsx
setData({ title: '新标题' });    // ← 直觉写法
```

**标题变成「新标题」，但内容整块消失了。** 作者的追问很生动：**「怎么内容没有了？我们找一下这个元素，div 是存在的，标题也变成了新标题，但是内容没有了。」**

> 「因为 `setData` 这个操作，它是把你传入的值**直接替换**掉旧值，而不是局部修改，它是一个直接换掉的操作。你之前不是两个值吗？用它一换就剩一个 title 了，content 就没有了。」

```
改之前： { title: '默认标题', content: '默认内容' }
setData({ title: '新标题' })
改之后： { title: '新标题' }        ← content 没了 → <div title="新标题"></div> 空白
```

📌 补充：**类组件的 `this.setState()` 是浅合并的**，只有函数组件的 `useState` setter 是替换的。这个差异经常坑到从类组件迁过来的人。记住一句：**setter 只做一件事——把旧值扔掉，换成你给的新值。**

### 9.3 修法一：老老实实写全

> **「如果希望进行对象的更新，你要把它写全，哪怕 content 的部分没有更改，你也需要写全。」**

```jsx
setData({ title: '新标题', content: '默认内容' });
```

作者验收：**「内容虽然没有改，但是标题更改了。」**

### 9.4 修法二：展开运算符

作者紧接着指出「写全」的毛病：**「如果属性比较多，你是不是会写很多重复属性？」** 于是引入展开运算符：

> **「`...` 可以将对象属性展开。你先写展开操作，等于是把原有属性放在这儿，然后再写一个新属性，同名属性后面的会覆盖前面的。」**

```jsx
setData({
  ...data,            // ① 把旧对象所有属性摊开铺平
  title: '新标题',     // ② 再覆盖同名字段 → { title:'新标题', content:'默认内容' } ✅
});
```

### 9.5 第三个坑：顺序写反，等于没写

> 「你要变更的这个属性一定要**后写**。你先写的话，就会导致旧的又把新的给盖掉了，跟没写一样。」

```jsx
setData({ title: '新标题', ...data });   // ❌ 旧值把新值盖回去
setData({ ...data, title: '新标题' });   // ✅ 展开在前，改动在后
```

现场验证：**「这时候保存刷新，我一点击，你发现没有什么变化，因为它跟之前是一模一样的。」**
**记忆法：展开永远放最前面，改动永远写最后面。**

### 9.6 📌 补充：函数式更新，什么时候必须用

视频全程用直接传值，在「新值只依赖当前值一次」时没问题。两种情况必须换：

```jsx
// ① 连续多次更新：React 批处理，count 是这一轮渲染时的旧值
setCount(count + 1); setCount(count + 1);   // ❌ 两次基于同一个 count，最终只 +1
setCount(prev => prev + 1); setCount(prev => prev + 1);   // ✅

// ② setTimeout / 异步回调：闭包捕获的是旧 data
setTimeout(() => setData(prev => ({ ...prev, title: '异步新标题' })), 1000);  // ✅
```

已有笔记 §4.4 更保守（「只要依赖旧值就用函数式」），两者不矛盾：视频写法能用，但一旦开始「基于现在算下一个」，就换函数式。

## 10. 第十章 数组状态：push 不行，一切靠新数组

### 10.1 先渲染出来

```jsx
const [data, setData] = useState([
  { id: 1, name: '小吴' },
  { id: 2, name: '小李' },
  { id: 3, name: '小花' },
]);

return <ul>{data.map((item) => <li key={item.id}>{item.name}</li>)}</ul>;
```

作者说「渲染是没有任何问题的」——第 5 章的 key 规则直接复用。

### 10.2 追加：不能 `push`

> **「是不能直接通过 push 来做的，因为这块你必须要通过 setData 来做处理。」**

```jsx
data.push({ id: 4, name: '小花猫' });        // ❌ 界面不会更新
setData([{ id: 4, name: '小花猫' }]);        // ❌ 只剩新元素（整体替换）
setData([...data, { id: 4, name: '小花猫' }]); // ✅
```

第二条错误和第 9 章一样。作者验收：**「我一点击你发现只剩这一个了，因为它会将你的新数组直接替换到旧数组。」**

**为什么 `push` 也不行**（📌 补充）：① 改的是原数组，没调 setter，React 收不到通知；② 即使重渲染，`data === 旧data` 为 `true`，React 认为没变、跳过；③ 直接改 state 里的对象会让快照模型失效，调试时看到的历史值全是错的。

### 10.3 那个 `id++` 的坑

这是本集最「真实」的一段：作者现场写错、发现、改了——但改法仍然不彻底。

```jsx
let id = 3;                                       // 组件体内声明
setData([...data, { id: id++, name: '小花猫' }]);   // 后置加加 → 撞上已有的 id=3
```

作者判断：**「这是后置加加对吧，那应该改成的是前置。」**

```jsx
setData([...data, { id: ++id, name: '小花猫' }]);  // 前置加加 → 4，这次对了
```

**但只是一次对。** 📌 补充：真正根因——`let id = 3` 写在组件函数体里，**每次重渲染都会重新执行，id 又重置成 3**：

```
第 1 次点击：id 3 → 4，新增 id=4 ✅   列表 [1,2,3,4]
第 2 次点击：组件重渲染，id 重新变成 3 → 又算出 4 ❌  列表 [1,2,3,4,4]
```

正确做法是让 id 从现有数据推出来：

```jsx
setData(prev => {
  const nextId = prev.length ? Math.max(...prev.map(d => d.id)) + 1 : 1;
  return [...prev, { id: nextId, name: '小花猫' }];
});
```

作者收尾也承认了：**「这个数据正常来说应该是后端给你返回的，所以不太需要我们去操心。」** 所以这段坑的真实价值不是教你生成 id，而是让你看清「**组件函数体里的普通变量，每次渲染都会重置**」。

### 10.4 往前插

> **「如果我现在希望前面加，我是不是就可以把这个数据移到后面来。」**

```jsx
setData([{ id: Date.now(), name: '小花猫' }, ...data]);
// 页面顺序：小花猫 → 小吴 → 小李 → 小花
```

作者点评：**「因为数组是有序的，所以你对数组进行的不同操作它也是不一样的。」** 追加用 `[...data, new]`，前插用 `[new, ...data]`。

### 10.5 删除：`filter`

需求：「删除掉数组里面 ID 为 2 的这一个」。作者的思路值得学：

> 「我是要删除某一个元素，那就可以通过数组的 `filter`，它非常常用。**操作的时候只要去想你最终希望要的数据是什么样的**，你就通过 filter 把它过滤掉就 OK 了。」

```jsx
setData(data.filter((item) => item.id !== 2));   // 留下 id 不等于 2 的
```

作者验收：**「刷新一下点击，是不是只剩了小吴跟小花了呀，小李就去掉了。」** 注意 `filter` 的参数是「**保留条件**」不是「删除条件」——写反了就变成只留 id=2。

### 10.6 数组操作总表（📌 补充）

作者结尾说：**「大家也可以尝试一下做一些更新或者排序之类的操作，它可能需要记住数组的不同方法。」** 展开成表（视频只演了增和删）：

| 操作 | 禁止（原地改） | 正确（返回新数组） | 备注 |
|---|---|---|---|
| 追加 / 前插 | `push` / `unshift` | `[...data, x]` / `[x, ...data]` | |
| 删除 | `splice(i, 1)` | `data.filter(d => d.id !== id)` | 不用管下标 |
| 修改某项 | `data[i].name = 'x'` | `data.map(d => d.id === id ? {...d, name:'x'} : d)` | 已有笔记 §8.4 |
| 排序 / 反转 | `data.sort()` / `reverse()` | `[...data].sort()` / `[...data].reverse()` | **这两个改原数组**，必须先复制 |
| 取前 N | `data.length = N` | `data.slice(0, N)` | `slice` 安全 |

**判断标准**：这个方法**改不改原数组**？改的（`push`/`pop`/`shift`/`unshift`/`splice`/`sort`/`reverse`）全部要先复制，或换成不改动的方法（`concat`/`slice`/`filter`/`map`/`[...arr]`）。

## 14. 自测题（含答案）

**Q1**　`return` 后换行写 JSX 不加括号，会发生什么？
<details><summary>答案</summary>JS 在 `return` 后自动插入分号，函数返回 `undefined`。表现：**不报错**、JSX 变灰、页面空白。</details>

**Q2**　`<>` 和 `<Fragment>` 有什么区别？
<details><summary>答案</summary>渲染结果一样（都不产生 DOM）。唯一区别：**`<>` 不能接受任何属性，包括 key**；`<Fragment>` 可写 `<Fragment key={id}>`。</details>

**Q3**　`<div title="divTitle">` 和 `<div title={divTitle}>` 的区别？
<details><summary>答案</summary>`{}` 是**表达式**，取变量值；加引号就变成**字符串字面量**，页面上直接显示 `divTitle`。规则：引号 = 写死，大括号 = 求值。</details>

**Q4**　key 的「唯一」是全局唯一吗？
<details><summary>答案</summary>不是，**同级唯一**即可。同一个 `map` 生成的兄弟元素互不相同；不同列表之间可以重复。</details>

**Q5**　为什么用数组下标当 key 会出问题？
<details><summary>答案</summary>下标代表「位置」而非「身份」。列表一旦插入/删除/排序，同一下标对应的数据就变了，React 会错误复用 DOM 和 state（输入框内容错位）。只有「列表永不重排」才勉强可用。</details>

**Q6**　`setData({ title: '新标题' })` 为什么会让 `content` 消失？
<details><summary>答案</summary>`useState` 的 setter 是**整体替换**不是合并。新对象没有 `content` 字段，替换后就真没了，渲染 `undefined` 即空白，且不报错。</details>

**Q7**　`setData({ title: '新', ...data })` 为什么改了等于没改？
<details><summary>答案</summary>对象字面量里同名键**后写覆盖先写**。`...data` 在后面，把旧 `title` 又铺回来。正确写法 `{...data, title: '新'}`。</details>

**Q8**　为什么 `data.push(x)` 之后界面不更新？
<details><summary>答案</summary>① 改的是原数组，没调 setter，React 不知道要重渲染；② 即使重渲染，`data` 引用没变，React 认为「没变」跳过。必须 `setData([...data, x])`。</details>

**Q9**　删除数组里 id 为 2 的项，`filter` 里写 `=== 2` 还是 `!== 2`？
<details><summary>答案</summary>`!== 2`。`filter` 的参数是「**保留条件**」不是「删除条件」——先想清楚你最终要什么数据。</details>

**Q10**　`let id = 3` 写在组件函数体里，为什么第二次点击会重复？
<details><summary>答案</summary>组件函数体**每次重渲染都重新执行**，`id` 又重置成 `3`，所以每次都算出同一个 id。正确做法：`Math.max(...data.map(d => d.id)) + 1`，或由后端返回。</details>

**Q11**　条件渲染切走的组件，内部 state 还在吗？
<details><summary>答案</summary>**不在了**。条件渲染是销毁再重建，子树 state 全部重置。要保留就用 CSS 隐藏，或把状态提到父组件。</details>

**Q12**　`onClick={handleClick}` 和 `onClick={handleClick()}` 的区别？
<details><summary>答案</summary>前者传**函数引用**，点击时才执行；后者是**函数调用**，渲染时立刻执行，把返回值（通常 `undefined`）给了 `onClick`。传参写 `onClick={() => fn(id)}`。</details>

## 16. 📌 补充：视频没讲但会踩的坑

按「踩中概率 × 排查难度」排序。

**① `useState` 的初始值不会「每次都更新」**

```jsx
const [list, setList] = useState(props.initialList);   // ❌ 以为 props 变了会重置
```

参数**只在首次挂载时使用**，之后永远忽略。解法：A（推荐）把 state 提到父组件；B 用 `key={props.id}` 强制重建组件；C（少用）用 `useEffect` 监听 props 变化再 setState。

**② 嵌套对象要逐层展开**

```jsx
// ❌ address 整个被换掉，street 丢了
setUser({ ...user, address: { city: '上海' } });
// ✅ 逐层展开
setUser({ ...user, address: { ...user.address, city: '上海' } });
```

视频只讲「一层对象要展开」，**嵌套对象每一层都要展开**，这是 9.2 那个坑的升级版。

**③ 渲染过程中调 setState → 无限循环**

```jsx
function App() {
  const [count, setCount] = useState(0);
  setCount(count + 1);        // ❌ 渲染里调 → 重渲染 → 再调 → ...
  return <div>{count}</div>;
}
```

报错 `Too many re-renders.`。**规则**：setState 只能出现在事件处理函数、`useEffect`、`setTimeout` 回调等「非渲染期」代码里。

**④ 更新是异步批处理的，别指望立刻读到新值**

```jsx
setContent('新内容');
console.log(content);      // ❌ 还是旧值
```

`setContent` 只是「排了个队」，函数继续往下执行时 `content` 仍是这一轮渲染的值。要在更新后拿新值，就在下一次渲染里拿（如放进 `useEffect([content])`）。

## 17. 一句话总结

> **React 的世界只有两件事：用 JSX（受 5 条硬规则约束）把界面「描述」出来，用 `useState` 把数据「换」进去——而所有 set 都是「造一个新值替换旧值」，所以你永远不能 `push`、不能直接改字段、展开运算符永远写在最前面。**
